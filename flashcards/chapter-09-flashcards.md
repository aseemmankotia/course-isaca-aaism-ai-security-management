## Chapter 9: AI Security Monitoring, Red-Teaming, and Continuous Evaluation — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | How many categories are in the OWASP Top 10 for LLM Applications (2025)? | 10 (LLM01–LLM10). Exam tip: LLM01 = Prompt Injection, LLM06 = Excessive Agency — both heavily tested for agentic AI risk. |
| 2 | How many core functions does the NIST AI Risk Management Framework (AI RMF 1.0) define? | 4 — Govern, Map, Measure, Manage. Exam tip: 'Measure' covers continuous evaluation and monitoring activities. |
| 3 | Data drift vs. Concept drift? | Data drift = input feature distribution changes over time. Concept drift = the input-output relationship itself changes. Exam tip: rising hallucination rate on stable input types signals concept drift. |
| 4 | Direct vs. Indirect prompt injection? | Direct: attacker types malicious instructions straight into the prompt. Indirect: malicious instructions are hidden in retrieved/external content (docs, web pages, tool outputs). Exam tip: indirect injection requires logging full retrieved context, not just the user's typed input. |
| 5 | Model drift vs. Data drift vs. Concept drift? | Model drift = umbrella term for performance degradation over time. Data drift = input distribution shift. Concept drift = input-output relationship shift. Exam tip: continuous evaluation should monitor all three as distinct signals. |
| 6 | What must be logged for an agentic AI system to support incident forensics? | Full session trace: user prompt, system prompt, retrieved context, intermediate reasoning/tool calls with inputs/outputs, final response, timestamps, and model/version ID. Exam tip: output-only logging fails forensic reconstruction. |
| 7 | What are the typical phases of an AI/LLM red-team exercise? | 1) Scoping & threat modeling, 2) Adversarial prompt/attack generation, 3) Execution against target system, 4) Impact assessment, 5) Reporting & remediation tracking. Exam tip: agentic systems add a phase specifically testing unauthorized tool/action invocation. |
| 8 | How should AI telemetry be integrated into an existing SOC? | Forward AI-specific logs (prompts, guardrail triggers, tool calls) into the existing SIEM, add AI-specific detection rules, and correlate with identity/network logs rather than building a siloed AI-only SOC. Exam tip: a siloed AI SOC is a common wrong-answer distractor. |
| 9 | Name three primary AI-specific detection use cases. | 1) Prompt injection/jailbreak attempts, 2) Data exfiltration via prompts/embeddings, 3) Abuse pattern spikes (repeated near-identical adversarial prompts). Exam tip: these map to OWASP LLM01, sensitive info disclosure, and abuse-rate anomaly monitoring. |
| 10 | What key fields belong in a minimum viable prompt/response audit log schema? | Timestamp, session/conversation ID, user/service identity, system prompt (or hash), user prompt, model + version, retrieved context references, tool calls (name+params+result), output, guardrail/filter decision. Exam tip: hashing the system prompt preserves integrity checking without exposing it in every log line. |
| 11 | What should trigger a retraining/re-tuning decision in a mature continuous evaluation program? | A predefined evaluation metric threshold breach (e.g., accuracy drop, hallucination rate rise, jailbreak success rate rise) sustained across a defined monitoring window — not a single complaint or fixed calendar date alone. Exam tip: 'calendar-only retraining' is a common wrong-answer distractor. |
| 12 | MITRE ATLAS vs. OWASP Top 10 for LLM Applications — scope difference? | MITRE ATLAS catalogs adversarial tactics/techniques against AI systems (modeled after ATT&CK), used for threat modeling and red-team design. OWASP LLM Top 10 lists top application-layer risk categories for LLM apps. Exam tip: use ATLAS to design red-team scenarios, OWASP Top 10 to categorize/report risks. |
