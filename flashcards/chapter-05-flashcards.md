## Chapter 5: AI Threat and Vulnerability Management: Adversarial ML and ATLAS Mapping — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Direct vs. indirect prompt injection — key difference? | Direct: attacker types the malicious instruction straight into the user input. Indirect: malicious instruction is hidden in external content (webpage, document, tool output, email) that the model retrieves/reads. Exam tip: RAG and browsing-enabled agents are the classic indirect injection vector. |
| 2 | Jailbreak vs. prompt injection — key difference? | Jailbreak = bypassing the model's own safety/alignment guardrails (e.g., role-play, DAN prompts) to get disallowed output. Prompt injection = hijacking the model's task/instructions via crafted input (direct or indirect), regardless of safety alignment. Exam tip: a jailbreak can happen with zero external data; injection always involves manipulating instructions/context. |
| 3 | Adversarial ML taxonomy: 3 core attack categories? | 1) Evasion — manipulate inference input to cause misclassification. 2) Poisoning — corrupt training/fine-tuning data or labels. 3) Extraction — reconstruct model parameters, training data, or behavior via systematic querying. |
| 4 | MITRE ATLAS — what is it and how does it relate to ATT&CK? | ATLAS = Adversarial Threat Landscape for AI Systems, a MITRE knowledge base of real-world AI/ML attack tactics and techniques. It reuses most ATT&CK Enterprise tactics and adds ML-specific ones (e.g., ML Model Access, ML Attack Staging) to cover the ML attack lifecycle. |
| 5 | ATLAS tactic for crafting adversarial examples that fool a deployed model at inference? | Defense Evasion — technique commonly cited as 'Evade ML Model.' Exam tip: this is inference-time manipulation, distinct from poisoning (training-time). |
| 6 | ATLAS tactic for building a surrogate model from harvested query/response pairs? | ML Attack Staging — the attacker trains a substitute/attack model using data collected from the target's inference API, typically followed by the Exfiltration tactic to remove the stolen model/capability. |
| 7 | OWASP Top 10 for LLM Applications (2025) — list the 10 categories. | LLM01 Prompt Injection, LLM02 Sensitive Information Disclosure, LLM03 Supply Chain, LLM04 Data and Model Poisoning, LLM05 Improper Output Handling, LLM06 Excessive Agency, LLM07 System Prompt Leakage, LLM08 Vector and Embedding Weaknesses, LLM09 Misinformation, LLM10 Unbounded Consumption. |
| 8 | Which OWASP LLM Top 10 category covers a backdoored fine-tuning dataset? | LLM04: Data and Model Poisoning. Exam tip: distinguish from LLM03 Supply Chain, which covers compromised third-party models/components/libraries rather than manipulated training data itself. |
| 9 | Model theft/extraction — primary defensive control? | Per-user/API-key rate limiting plus anomaly detection on query volume, diversity, and output entropy. Exam tip: this is the first-line control cited for mitigating ATLAS 'ML Attack Staging' and 'Exfiltration' via inference API abuse. |
| 10 | Supply-chain compromise in AI systems — two main vectors tested on the exam? | 1) Compromised/tampered pretrained models or weights sourced from public hubs. 2) Poisoned or mislabeled third-party training/fine-tuning datasets. Mitigation: AIBOM (AI Bill of Materials) and provenance/checksum verification before use. |
| 11 | Targeted vs. availability (indiscriminate) data poisoning — difference? | Targeted poisoning inserts a specific trigger/backdoor causing a chosen malicious output for specific inputs while model behaves normally otherwise. Availability poisoning degrades overall model accuracy broadly, making it unusable. Exam tip: targeted poisoning is stealthier and harder to detect via aggregate accuracy metrics. |
| 12 | Membership inference attack — what does it reveal, and which OWASP/ATLAS category does it map to? | Reveals whether a specific record was part of a model's training data, risking privacy/PII disclosure. Maps to OWASP LLM02 (Sensitive Information Disclosure) and ATLAS 'Exfiltration' tactic via inference querying. |
